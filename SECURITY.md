# ASCII Meadow — безопасность

- Репозиторий и GitHub Actions являются **публичными**. Никогда не коммитьте и не публикуйте секреты, API-ключи, токены Cloudflare/GitHub/AI, `.env`, `.dev.vars`, service-account JSON или приватные ключи. Секреты храните только в локальном окружении или защищённом хранилище провайдера.
- В **каждом** локальном клоне (в том числе у Claude) выполните `sh tools/security/install-hooks.sh`. Скрипт включает проверку staged-версий до коммита, без передачи содержимого в сеть.
- CI запускает `tools/check/secret-history.py` по истории веток и PR; публичные логи содержат только категории находок. Сборка Cloudflare блокируется через `tools/check/deploy-surface.cjs` при обнаружении подозрительных ключей или посторонних файлов.
- Если секрет всё же появился где-либо в push, PR, GitHub Actions, бинарном артефакте или deployed-сайте: **сначала немедленно отзовите/замените секрет у провайдера**, затем удалите файл из рабочих веток и скоординируйте переписывание истории с участниками. Изменение истории **не отзывает** уже скопированный секрет.
- Не сообщайте реальные секреты в публичных issues, PR, логах или AI-чатах. Для приватного сообщения об уязвимости используйте GitHub Private Vulnerability Reporting, если оно включено, или защищённый канал связи с владельцем проекта.
- В настройках GitHub необходимо отдельно включить **Secret scanning**, **Push protection** и **rulesets** для `main` и `experiment/threejs-ascii-prototype` (запрет force push, удалений, требование успешной секрет-проверки). Доступное этому агенту GitHub-подключение не может изменить эти административные настройки.
- Сканеры используют эвристики и не гарантируют обнаружение нестандартных или неизвестных секретов, а также скрытого содержимого бинарных файлов.
