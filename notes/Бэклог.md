## 2026-10-12 — собственные PNG-атласы NPC (этап 1б.2, PR #19)

Новая необязательная ветка рендера `src/entities/npc-atlas.js`: `npcAtlasLayout()` валидирует размеры каждого кадра (8–1024 px), состояния `idle/walk/talk`, скорость кадров (1–60 fps), число кадров (1–60) и номер строки PNG для одного ракурса или всех восьми направлений. Нумерация направлений соответствует движку: **S, SW, W, NW, N, NE, E, SE**. `npcAtlasAttach(type, layout, png)` принимает только локальные `assets/npc/*.png`, временные blob URL или тестовые `data:image/png`; источник асинхронно проверяется по реальным размерам изображения. При отсутствии, ошибке загрузки или неподдержанном состоянии применяется исходный процедурный риг. `npcAtlasFrame()` рассчитывает кадр по времени NPC либо фазе ручного предпросмотра, `npcAtlasPreviewImage()` строит изображение только на отдельном буфере. Отрисовка работает через прежнюю ASCII-пайплайн `drawEntity()`, без второго мирового рендера.

Редактор `?edit`: выберите тип в каталоге, укажите ширину/высоту кадра, нажмите «Выбрать PNG-атлас»; строка 0 = idle, 1 = walk, 2 = talk, а при недостатке строк используются доступные. Колонки = последовательные кадры. Локальная загрузка **только для текущей вкладки** и не включается в `map.js`: для постоянного использования PNG нужно добавить в `assets/npc/` и зарегистрировать `npcAtlasAttach(...)` из исходного JS; нельзя выдавать временный `blob:` за ассет сборки. На исходной карте NPC не размещаются автоматически, атласы рыцаря и коров не затронуты.

Контракт регресса: `tools/check/npc-atlas.cjs` и `tools/check/npc-atlas-browser.cjs` проверяют валидацию, запрет внешних URL, fallback, тестовый PNG, редакторский импорт, реальный draw path в WebGL2/Canvas 2D и идентичность исходного экспорта карты. Визуальные сценарии игры остаются blocking. **Нет:** художественных NPC-атласов в репозитории, авторских 60 кадров на направление, сериализации PNG в карту или 3D-поворота сверх имеющихся восьми направлений. Этап 1б.2 закрывать только после зелёного CI, оценки скриншотов и готового художественного ассета. PR: https://github.com/aostera/ASCII-Meadow/pull/19

### 2026-10-12 — проверка качества PNG-атласов NPC (PR #19)

В редактор добавлена **ручная** (не при каждом кадре) кнопка «Проверить качество PNG». `src/entities/npc-atlas-audit.js` выполняет ограниченное по памяти считывание каждого заявленного кадра на сетке 32×32 и возвращает структурированный отчёт: `blank-frame` (пустой прозрачный кадр, ошибка), `empty-direction` (вся линия направления пуста, ошибка), `duplicate-frame` (одинаковые соседние кадры, предупреждение: для idle допустимо), `duplicate-direction` (одинаковая анимация в нескольких из 8 ракурсов, предупреждение), `bounds-jump` (резкая смена размеров/центра силуэта, предупреждение). Для каждого замечания указываются состояние, ракурс и номер кадра, когда применимо. Отчёт read-only, выводит не более 25 замечаний с количеством остальных. Точность диагностики ограничена 32×32 downsampling; это предварительная проверка, **не гарантирует** качество рисунка и не заменяет просмотр художником. Мировой рендер и `map.js` не меняются. Тестовые PNG находятся только в CI, постоянные художественные атласы пока не поставляются. https://github.com/aostera/ASCII-Meadow/pull/19


### 2026-10-12 — визуальная библиотека NPC-анимаций (PR #19)

При наличии подтверждённого 8-направленного PNG для выбранного персонажа и состояния добавляется матрица из 8 ракурсов, по два кадра на каждый; при процедурном риге или одностороннем PNG матрица не имитирует 360° и выводит пояснение. Клик по миниатюре переключает тип, состояние, направление, фазу кадра, ставит предпросмотр на паузу; **не создаёт NPC, не правит карту и не модифицирует атлас**. Миниатюры используют тот же монохромный символьный алгоритм и исходный процедурный/PNG риг, отрисовываются только при открытии библиотеки или изменениях в редакторе, не каждый симуляционный кадр. Для архитектуры: отдельный `src/editor/npc-gallery.js` загружается сразу после `editor.js`, без изменений исходных атласов рыцаря и коров. **Ограничение:** contact sheet — до 4 кадров на строку и 2 на ракурс, для точной проверки всех 60 кадров служит основной таймлайн. Не заявлять художественные NPC-атласы, пока они не созданы. CI/визуальное ревью до merge обязательны. https://github.com/aostera/ASCII-Meadow/pull/19


### 2026-10-12 — starter PNG: Странник, 8 направлений (PR #19)

В `assets/npc/villager-starter.png` создан **реальный постоянный** монокромный прототип спрайта Странника (плащ, капюшон, пояс, сумка) в совместимом формате палитрового PNG с прозрачностью: **480×1344 px**, кадр **40×56 px**, 12 кадров на каждое состояние/направление, 3 состояния × 8 направлений = 288 кадров. Порядок рядов: `idle` 0–7 (6 FPS), `walk` 8–15 (12 FPS), `talk` 16–23 (8 FPS), направление S, SW, W, NW, N, NE, E, SE. Арт воспроизводимо генерируется командой `node tools/npc/generate-villager.cjs`; он является **прототипом**, НЕ внешне иллюстрированным финальным ассетом. Манифест `src/data/npc-atlases.js` теперь подключает его при старте игры; для существующей карты v1 NPC не создаются автоматически, оригинальные атласы рыцаря и коров нетронуты. Тесты исправлены под новый реальный восьмиракурсный предпросмотр и проверяют, что Отшельник остаётся процедурным. Перед художественной приёмкой нужны ручной обзор, проверка читаемости ASCII и доработка анимационных ключей. Stage 1б.2 остаётся Draft. https://github.com/aostera/ASCII-Meadow/pull/19


### 2026-10-12 — интерактивный отчёт качества NPC-атласа (PR #19)

Добавлен переход **из конкретного замечания в таймлайн**: после нажатия «Проверить качество PNG» результаты представлены доступными с клавиатуры кнопками. Клик по проблеме открывает соответствующие `type/state/direction/frame` в основном ASCII-предпросмотре и приостанавливает анимацию; при замечаниях для направления в целом выбирается первый кадр, при `all` — южный ракурс. Ошибки остаются read-only, исходный PNG и `map.js` не меняются. Ограничение 25 строк сохраняется, полные данные можно скачать кнопкой «Скачать отчёт JSON» (версия 1, тип, метрики, полный массив находок, **без** PNG/blob и игровых данных). При смене PNG или анимационных настроек отчёт аннулируется. Это позволяет обрабатывать художественные дефекты на сотнях кадров. CI текущего коммита ожидает полный прогон; PR остаётся Draft.

## 2026-10-12 — архитектура действительно объёмная, масштаб персонажей

Требование автора: шесть показанных 3D-референсов должны считываться в ASCII Meadow как пространственные готические конструкции, а не плоские фасады. Пакет `art/volumetric-gothic-npc-scale-20261012`: реальная 3D-геометрия с оконными прорезями через толщину кладки, двухслойными архивольтами, выступающими контрфорсами, поперечными нервюрами, разной высотой разрушенных стен и настоящим самозатенением; контактные и падающие тени на земле. Замок, старая дизайнерская карта и оригинальные спрайты рыцаря/коров оставлены на месте.

**NPC:** прежнее правило «48 видимых строк из 56» недостоверно для высоких капюшонов, шляп и посохов; полный 56-строчный атлас теперь занимает не более **72% реальной видимой высоты рыцаря**, сохраняет исходные пропорции и ставится ногами в землю. Прямоугольник перекрытий соответствует фактической области отрисовки.

**Границы:** это объёмный ASCII-рендер трёх игровых зданий, а не импорт исходных 3D-моделей из изображений. Пиксельное совпадение «1 в 1» с шестью изображениями пока **не подтверждено**: после CI нужны ручная композиционная и художественная приёмка ракурса, силуэтов и пропорций. Visual diff помечен `visual-change`, снимки тестов сохраняются. Проверка FPS обязательна после нового raycast bake.
