Этапы внедряются отдельными PR, с обязательным сохранением внешнего вида, `src/data/map.js`, игрового поведения и Cloudflare-сборки.

- [x] **Этап 1а (ветка `architecture/actor-catalog-stage1`)** — каталог типов новых NPC, уникальные ID, создание/удаление, idle/wander, реплики, позиции в мировых координатах, unit + браузерные тесты. Существующих рыцаря и коров пока не мигрировать.
- [x] **Этап 1б.1 (PR #18)** — NPC в редакторе: создание, перемещение, выбор типа, удаление и Undo/Redo; версия карты v2 с массивом actors и валидацией импорта. Старый map.js остаётся v1, пока автор не разместит NPC.
- [ ] **Этап 1б.2** — универсальные профили кадров/анимаций и состояний для новых видов, не затрагивая базовые атласы рыцаря и коров; добавить библиотеку ассетов/предпросмотр вариантов NPC.
- [x] **Этап 2а (PR #17)** — единый реестр типов действий, выбор ближайшей точки, проверка условий/дистанции, безопасное использование после удаления NPC, последовательные реплики по E, перевод ворот на inspect; unit- и браузерные тесты.
- [ ] **Этап 2б** — диалоговый интерфейс и ответы, инвентарь, предметы, двери, торговля, основа боя. Не считать реализованными до согласования правил и проверки состояния сохранений.
- [ ] **Этап 3** — Scene Manager: зоны, помещения, интерьеры, переходы и точки входа/выхода, независимые состояния.
- [ ] **Этап 4** — мир по чанкам: загрузка ближайших областей, обновление только активных NPC, отказ от полного пересоздания карты при каждом изменении окна.

**Граница этапа 1а:** каталог типов сам по себе не даёт NPC в рабочей карте после перезагрузки, не включает анимации произвольных атласов и не реализует диалоги с выбором, предметы или интерьеры. Следующий этап начинать после успешного CI и подтверждения автора.

## 2026-10-12 — NPC rig motion (draft, PR pending)

Проблема: новым NPC нужны отдельные параметры движения без изменения оригинальных кадров рыцаря, коров и карты. Решение: валидируемые `rigMotion` (`idle.breath`, `walk.stride`, `talk.breath`) в каталоге типов и применение только к процедурному `pose(e)`; добавлен не размещённый на карте тип `hermit`. Ограничения: это не поддержка произвольных покадровых атласов и не готовая библиотека ассетов/предпросмотр. Проверяемый результат: параметры ограничены и заморожены; требуется CI, визуальная проверка и тесты. Для кейса: сравнительная галерея поз NPC и схема пути type → profile → pose. Ссылка на PR будет добавлена после его создания.


### 2026-10-12 — NPC catalog preview (PR #19, WIP)

В редакторе карты добавлена информационная панель выбранного NPC: имя, ID типа, риг, поведение, коэффициенты шага и дыхания. Это read-only просмотр параметров, без спавна и изменения карты. **Ограничения:** не визуальный предпросмотр кадров, не библиотека загружаемых атласов. Проверки этого коммита пока ожидаются; не отмечать этап 1б.2 выполненным. Портфолио: скриншот панели NPC и схема данных тип → профиль → риг. PR: https://github.com/aostera/ASCII-Meadow/pull/19


### 2026-10-12 — схематичный NPC pose preview (PR #19)

Добавлен изолированный canvas-предпросмотр скелетной позы в редакторе NPC с ручным выбором idle/walk/talk. Используется `pose()` на временном объекте, без `spawnActor`, изменения карты, рендера игрового мира или RNG. **Не является** предпросмотром готового ASCII-атласа или анимацией 60 кадров. Ограничения: статичные контрольные позы, CI текущего изменения пока не подтверждён. Визуалы для портфолио: скриншоты трёх состояний и схема разделения editor preview / world renderer. PR: https://github.com/aostera/ASCII-Meadow/pull/19


### Пакет QA для NPC preview (12.10.2026, PR #19)
