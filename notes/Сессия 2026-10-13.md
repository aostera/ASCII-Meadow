1. Исправить тени и взаимодействие травы у палаток/заборов как у рыцаря.
2. Корректно перекрывать деревья передними зданиями/палатками.
3. После первого исправления пользователь сообщил о главном блокере: в опубликованной игре видна старая карта и старое поведение, хотя GitHub main обновлён.
4. Подробно фиксировать изменения для Claude, чтобы при передаче работы не терялся контекст.

## Отрисовка и сцена

- `src/renderer/render.js`: `coverFloraWithArchitecture(f)` восстанавливает ближайшую каменную геометрию замка/руин поверх нарисованной флоры, сравнивая `dep` с опорой объекта; не перекрывает всё растение безусловно. Палатки/деревья по-прежнему упорядочиваются Y-sort; визуальная проверка произвольных ракурсов открыта.
- `src/world/camp.js`: у палатки collision и скрытие травы разделены (`v.block` физический, `v.hide` пуст); у fence hide только у опор. Тень от повёрнутых solids использует 3 samples к `LGT`.
- `src/world/grass.js`: `applySceneryGrassForces()` использует градиент `campGround` для отгибания травинок на краю реального footprint; позднее 13 октября слабая сила `dx*1.25` была заменена на нормализованный толчок с ограничением и смягчённое постоянное `flat` у основания, чтобы реакция читалась на фоне ветра.
- `src/world/ruins.js`: `RUIN_FLORA_BUFFER` 72→24, деревья позади ближе к стенам, прежние архитектурные коллизии сохранены.
- `tools/check/scenery-depth-browser.cjs`: browser checks для masonry depth, grass/collision/shadow и искусственного контактного градиента, проверяющего реально сильный `push` и `flat` (desktop WebGL2 / mobile Canvas2D).

## Диагностика продакшена

Первоначальная проблема была в отсутствии независимой проверки опубликованных файлов. GitHub CI подтверждал локальную сборку, Cloudflare Workers Builds отмечал success, но никто не сравнивал публичный endpoint с `src/data/map.js`.

- `tools/check/production-parity.cjs`: HTTPS-проверка реальных URL `index.html`, `build.json`, `src/data/map.js`, `src/renderer/render.js`, `src/world/{grass,camp,ruins,flora,shadows}.js`. Сравнивает побайтово с локальным checkout и генерируемым `dist/index.html`, допускает время на выкладку, сообщает конкретные расхождения. Не путать success GitHub с success реального production.
- `.github/workflows/ci.yml`: отдельный production-parity job при push в main, сначала собирает `dist/`, затем сверяет с публичным сайтом. Первый запуск на исходных URL (до кеш-фикса) успешно подтвердил, что опубликованные ресурсы совпадают с `main`, значит отсутствие файлов на сервере не объясняет все случаи старой сцены.
- `tools/build_site.sh`: на каждой сборке добавляет `?v=<git-commit>` ко всем локальным скриптам и CSS В ПУБЛИКУЕМОМ `dist/index.html`, оставляя исходный `index.html` без изменений; пишет `dist/build.json`, добавляет `dist/_headers` с `Cache-Control: no-store` для HTML, манифеста, CSS/JS. Это предотвращает выдачу старых модулей при обновлении страницы и помогает расследовать проблемы кеширования.
- Новый `src/data/map.js` пользователя и расположение объектов НЕ переписывались.

## Проверено и не проверено

- На коммите `9ea8177` первый network production parity job прошёл; публичные `index.html`, карта и renderer исходно побайтово совпадали с main.
- На следующем versioned build аналогичная проверка сравнивает `dist/index.html` с public resource и файл `build.json`. Реальный статус финального HEAD получать по CI отдельно, без выдачи неподтверждённых гарантий.
- Отдельно остаётся визуальная проверка реальной сцены и её работы после долгого открытого таба Safari. Продолжить тестировать WebGL2/Canvas2D, мобильный viewport, перекрытия деревьев/палаток и тень при переносе объекта через редактор.
- Для старой открытой вкладки уже выполняющийся JS не заменяется автоматически до перезагрузки страницы. Новые ссылки `?v=` помогут после reload; при необходимости реализовать явное оповещение об обновлении, не теряя несохранённое состояние редактора.
