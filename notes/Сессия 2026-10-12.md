## 2026-10-12 — собственные PNG-атласы NPC (этап 1б.2, PR #19)

Новая необязательная ветка рендера `src/entities/npc-atlas.js`: `npcAtlasLayout()` валидирует размеры каждого кадра (8–1024 px), состояния `idle/walk/talk`, скорость кадров (1–60 fps), число кадров (1–60) и номер строки PNG для одного ракурса или всех восьми направлений. Нумерация направлений соответствует движку: **S, SW, W, NW, N, NE, E, SE**. `npcAtlasAttach(type, layout, png)` принимает только локальные `assets/npc/*.png`, временные blob URL или тестовые `data:image/png`; источник асинхронно проверяется по реальным размерам изображения. При отсутствии, ошибке загрузки или неподдержанном состоянии применяется исходный процедурный риг. `npcAtlasFrame()` рассчитывает кадр по времени NPC либо фазе ручного предпросмотра, `npcAtlasPreviewImage()` строит изображение только на отдельном буфере. Отрисовка работает через прежнюю ASCII-пайплайн `drawEntity()`, без второго мирового рендера.

Редактор `?edit`: выберите тип в каталоге, укажите ширину/высоту кадра, нажмите «Выбрать PNG-атлас»; строка 0 = idle, 1 = walk, 2 = talk, а при недостатке строк используются доступные. Колонки = последовательные кадры. Локальная загрузка **только для текущей вкладки** и не включается в `map.js`: для постоянного использования PNG нужно добавить в `assets/npc/` и зарегистрировать `npcAtlasAttach(...)` из исходного JS; нельзя выдавать временный `blob:` за ассет сборки. На исходной карте NPC не размещаются автоматически, атласы рыцаря и коров не затронуты.

Контракт регресса: `tools/check/npc-atlas.cjs` и `tools/check/npc-atlas-browser.cjs` проверяют валидацию, запрет внешних URL, fallback, тестовый PNG, редакторский импорт, реальный draw path в WebGL2/Canvas 2D и идентичность исходного экспорта карты. Визуальные сценарии игры остаются blocking. **Нет:** художественных NPC-атласов в репозитории, авторских 60 кадров на направление, сериализации PNG в карту или 3D-поворота сверх имеющихся восьми направлений. Этап 1б.2 закрывать только после зелёного CI, оценки скриншотов и готового художественного ассета. PR: https://github.com/aostera/ASCII-Meadow/pull/19

### 2026-10-12 — безопасность при открытии игры через file:// (PR #19)

При подключении постоянного PNG обнаружен браузерный `SecurityError`: Chromium загружает `file://assets/npc/villager-starter.png`, но считает canvas с этим изображением tainted; чтение `getImageData()` в ASCII-пайплайне падает. Исправлено через однопиксельную проверку доступности чтения внутри `npcAtlasAttach().onload`: при ошибке `entry.status='error'`, рендер и редактор автоматически используют процедурный риг. При запуске по HTTP ресурс same-origin и должна использоваться настоящая PNG-анимация, что проверяется новым браузерным тестом HTTP-сервера. Карта, рыцарь и коровы остались без изменений. PR не сливать до зелёного CI.


### 2026-10-12 — интерактивный отчёт качества NPC-атласа (PR #19)

Добавлен переход **из конкретного замечания в таймлайн**: после нажатия «Проверить качество PNG» результаты представлены доступными с клавиатуры кнопками. Клик по проблеме открывает соответствующие `type/state/direction/frame` в основном ASCII-предпросмотре и приостанавливает анимацию; при замечаниях для направления в целом выбирается первый кадр, при `all` — южный ракурс. Ошибки остаются read-only, исходный PNG и `map.js` не меняются. Ограничение 25 строк сохраняется, полные данные можно скачать кнопкой «Скачать отчёт JSON» (версия 1, тип, метрики, полный массив находок, **без** PNG/blob и игровых данных). При смене PNG или анимационных настроек отчёт аннулируется. Это позволяет обрабатывать художественные дефекты на сотнях кадров. CI текущего коммита ожидает полный прогон; PR остаётся Draft.
