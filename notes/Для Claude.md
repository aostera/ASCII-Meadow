# Для Claude: как вернуться к работе

Связано: [[ASCII Meadow]] · [[Техническая архитектура]] · [[Визуальное направление]]

## Где что лежит
- Репозиторий `aostera/ASCII-Meadow`, ветка `main`. Игра — `index.html` (только точка входа) + `styles/main.css` + `src/` (код по подсистемам, кадры в `src/data/`), заметки — `notes/`. Карта файлов и правила размещения кода — [[Техническая архитектура]].
- Опубликованный артефакт: https://claude.ai/artifact/J3wgnky6xvhkRMzyJTyV14 (обновлять по этому `url`, сначала `read`).
- Артефакт без обёртки `<html>/<head>/<body>`; в репозитории — та же страница, обёрнутая в полный документ.

## Пользователь
- UX/UI, продуктовый и моушн-дизайнер. Пишет по-русски, коротко. Отвечать по-русски.
- Ценит визуальную точность больше технических объяснений. Эталон — видео.
- Перед заменой стиля — спросить или сверить с референсом. «Один в один» значит использовать исходник, а не рисовать заново.

## Правила, которые пользователь повторял
- Помнить про оптимизацию в каждом изменении: считать один раз и кешировать, рисовать только видимое, мерить CPU кадра.
- Движение должно быть реалистичным, без «желе»: всё качается от одного ветра, тяжёлые вещи медленно.
- Анимируя то, что уже переведено в символы, двигать глифы, а не пересчитывать дизеринг: пересчёт даёт рывки и мерцание.
- Существа в мире (коровы и т. п.) — как деревья: тёмная масса, свет только по верхнему краю, ноги в траве. Не светлые спрайты.
- Части тела животных двигать жёстким поворотом вокруг сустава, а не растяжением/синусами — иначе «желе». Смену рисунков — растворять, не прыгать.
- Плащ — отдельный слой со своей физикой; рисовать отдельно от тела.
- Плащ в движении — как в ассетах (кадры атласа символами), не деформировать его кодом: «странная анимация».
- Ветер двигает только плащ (маска `KCLOAK`, обведена по атласу); рыцарь в стойке стоит и чуть дышит. Угадывать плащ по геометрии нельзя — задевает тело. На границе движущегося и неподвижного — плавный переход в несколько символов, иначе виден срез. Смещения соседних строк одной области должны быть почти равны — иначе полосы.
- Ноги при ходьбе не ломать и не перекрещивать: двигать в пределах нарисованной формы. Проверять шаг на чистом фоне (галерея фаз), а не в траве: трава прячет ноги.

## Ввод
- Пользователь на русской раскладке: клавиши только через `e.code`.

## Как работать
1. Перед правкой перечитать [[Визуальное направление]].
2. После правки: `npm run check:static` и `npm run check:browser` (см. `tools/check/README.md`); при переносе кода — детерминированная сверка `tools/check/` (до/после попиксельно; на PR это делает CI), скриншоты Playwright (`/opt/pw-browsers/chromium`, для WebGL флаги `--use-angle=swiftshader --enable-unsafe-swiftshader`), проверить: десктоп, iPhone, старт с нулевым размером панели.
3. В программном рендере fps низкий (~5) — это не реальная цифра. Мерить CPU отдельно, отключив `GL.flush`.
4. Если меняются кадры рыцаря: `tools/to_ascii.py` → вставить `KNIGHT_ART` в `src/data/knight-frames.js`, затем `node tools/find_blades.cjs` → вставить `KSW` туда же. Кадры коров — `COW_ART`/`CIX` в `src/data/cow-frames.js` и `src/entities/cow.js`.
5. Опубликовать артефакт (страница + файлы `src/`, `styles/` через `files`, или одним файлом через `tools/bundle.py`), закоммитить, обновить [[Хронология]] и [[Бэклог]].
6. Новый код — никогда не в `index.html`: свой файл в `src/`, `<script>` в правильном месте, вызов из `simulate()`/`render()`.

## Система взаимодействий (этап 2а, PR #17)

- Действия `E` и нажатие на подсказку идут через `useSpot()` → `performInteraction(activeSpot)` в `src/systems/interactions.js`. Выбор ближайшей точки выполняет `pickInteraction()`; он проверяет радиус, `need()`, существование NPC. Не добавлять прямой вызов действия, обходящий эти проверки.
- Для обычного объекта можно использовать прежний формат `{x, y, r, label, use()}`; для типизированного объекта — `{x, y, r, label, action: 'inspect', onUse()}`. У ворот уже используется inspect, но дверь намеренно **не** открывается: исходная реакция сохраняется.
- `spawnActor(...)` с непустыми `lines` получает действие talk автоматически: `E` показывает следующую реплику; исчезнувший NPC и NPC вне досягаемости не могут обрабатываться старым выбором.
- Новый тип `open`/`take`/`trade`/`attack` добавлять только вместе с работающей логикой, состоянием/сохранениями и тестом. Не вводить пустые обработчики.
- Для QA: `node tools/check/interactions.cjs`, `node tools/check/interactions-browser.cjs`, затем **весь** CI с попиксельными сравнениями; `src/data/map.js`, расположение объектов, рыцарь и коровы не изменяются.
- Продолжать вести `notes/Хронология.md`, `notes/Бэклог.md`, `notes/Техническая архитектура.md` и `notes/Сессия 2026-10-11.md` при каждом архитектурном PR. Никаких незафиксированных больших изменений в main.

## Карта
- Карта игры — `src/data/map.js` (`MEADOW_MAP`), её рисует пользователь в редакторе (кнопка или M; пока открыт всем, потом — тайная комбинация: флаг `EDIT` в `src/world/map.js`). «Сохранить» скачивает `map.js`; пользователь присылает файл — положить его как `src/data/map.js` (проверить, что это только комментарии и `const MEADOW_MAP = {JSON};`), прогнать проверки и выкатить в `main`. Не перезаписывать её генерацией: `null`-поля = генерация, заполненные — его работа.
- Новый вид объекта на карте: поле в `MEADOW_MAP`, расстановка в `world/map.js` (по образцу `placeGroundFires`), инструмент в `ED_OBJECTS` и ветка в `edPlace`/`edBake` (`editor/editor.js`), проверка в `smoke.cjs`.

## Архитектура персонажей: этап 1 (2026-10-11)

- Перед дальнейшим расширением прочитать [[Техническая архитектура]], секцию **«Рост контента: каталог NPC»**, и [[Бэклог]], секцию **«Масштабирование игры»**.
- Новый NPC: `registerActorType(id, {name, renderClass: 'human' | 'dwarf', tint, lines, behavior: 'idle' | 'wander', speed})`, затем **после старта игры** `spawnActor(id, {id: 'stable-id', world: [x,z]})`. Функция `despawnActor(id)` удаляет из `npcs` и `ents`. Файл: `src/entities/catalog.js`, подключён после `entities/entities.js`.
- По умолчанию регистрируется только тип `villager`, а экземпляры **не** создаются. Не менять число NPC и финальный кадр без запроса автора. Рыцарь и коровы используют проверенные специализированные анимации.
- После изменения размеров окна новые NPC репроецируются через `snapshotActorWorld`/`restoreActorWorld`. Не задавать NPC постоянные координаты в пикселях или клетках холста; `world: [x,z]` — единицы карты.
- Прежде чем расширять `MEADOW_MAP` полем NPC, подготовить **новую версию формата**, миграцию импортёра и тест сохранения один-в-один. Сейчас NPC, добавленные программно, при перезагрузке страницы не сохраняются.
- Новые тесты: `node tools/check/actors.cjs`, `node tools/check/actors-browser.cjs`. Оба выполняются в CI вместе с исходными тестами, не заменяют их.

## Ведение проекта и качество

Пользователь требует того же подробного учёта, что раньше в Obsidian:
1. **Каждый значимый шаг:** `notes/Хронология.md` — номер, техническое изменение и причина/запрос автора.
2. **Архитектура:** `notes/Техническая архитектура.md` — файлы, порядок подключения, API, ограничения и тесты.
3. **Задачи:** `notes/Бэклог.md` — выполненное и следующие этапы.
4. **Передача контекста:** этот файл и отдельная запись `notes/Сессия YYYY-MM-DD.md`.
5. **Проект и README:** только подтверждённые возможности; не выдавать фундамент системы за готовую игру с новыми функциями.
6. Каждую часть менять отдельной веткой/PR, не переписывать карту `src/data/map.js` и не отключать визуальные регрессии. Объединять только после полного успешного CI и оценки сохранности картинки.

## Карта с NPC: v1 и v2 (PR #18)

- **Не редактировать старый `src/data/map.js` вручную и не перегенерировать его.** Формат `v1` без `actors` остаётся прежним. При первом добавлении NPC редактор создаёт `v2` с `actors: [[id, type, x, z], ...]`, включая уникальные ID и мировые координаты.
- Инструмент `NPC` (N) и выбор варианта работают только с типами из `ACTOR_TYPES` (`src/entities/catalog.js`). Новые виды персонажей требуют регистрации типа и графики, а не вставки произвольного текста в `map.js`.
- `syncMapActors()` создаёт лишь NPC, описанных в карте (флаг `fromMap`); независимых NPC из кода не удаляет. `placeEntities()` вызывает синхронизацию после построения мира, редактор — после редактирования массива.
- Обязательная проверка: `node tools/check/map-import.cjs`, `node tools/check/map-npcs.cjs`, `node tools/check/map-roundtrip.cjs`, далее все существующие CI и visual diff. Проверяй сохранение, загрузку в новом браузере, мобильный экран и Undo/Redo.
- Обновление map.js от автора — только исходным файлом и через `tools/map/import.cjs <файл> --apply`, без реконструкции позиций. Поддержка v2 не означает, что текущая карта автоматически переведена на v2.

## Публикация
- Сайт: https://ascii-meadow.aloster36.workers.dev/ — Cloudflare Workers (бесплатно), Worker `ascii-meadow`, Workers Builds подключён к GitHub (репозиторий публичный с 2026-10-11). Пуш в `main` → деплой (`npx wrangler deploy`), другие ветки → превью (`npx wrangler preview`, поэтому в `wrangler.jsonc` есть `previews: {}`). Build command в панели не нужен: `npm ci` запускает `prepare` → `sh tools/build_site.sh dist`. Без `wrangler.jsonc` Wrangler сам настраивает проект и заливает весь репозиторий с `node_modules` — сборка падает. Лог сборки виден только в панели Cloudflare (MCP его не отдаёт).
- После деплоя проверять живой сайт: `node tools/check/smoke.cjs https://ascii-meadow.aloster36.workers.dev/` (26 проверок: WebGL2, 2D, касания, консоль).
- GitHub Pages не используется (сайт развёрнут через Cloudflare); workflow Pages удалён. Репозиторий теперь публичный, GitHub Actions на стандартных hosted runners работает.
- Артефакт claude.ai публикуется склейкой: `python3 tools/bundle.py <файл> --body`.


## 2026-10-12 — NPC rig motion (draft, PR pending)

Проблема: новым NPC нужны отдельные параметры движения без изменения оригинальных кадров рыцаря, коров и карты. Решение: валидируемые `rigMotion` (`idle.breath`, `walk.stride`, `talk.breath`) в каталоге типов и применение только к процедурному `pose(e)`; добавлен не размещённый на карте тип `hermit`. Ограничения: это не поддержка произвольных покадровых атласов и не готовая библиотека ассетов/предпросмотр. Проверяемый результат: параметры ограничены и заморожены; требуется CI, визуальная проверка и тесты. Для кейса: сравнительная галерея поз NPC и схема пути type → profile → pose.
