# ASCII Meadow

Прототип мира в духе ASCII-MMORPG: вид сверху, всё нарисовано символами.

- Высокая трава с физикой: ветер, порывы, трава расступается вокруг рыцаря и закрывает его ноги.
- Тропинка петляет через поле к огромному готическому замку. Замок — 3D-модель, которая один раз прорисовывается лучами в сетку символов: свет, тени, окна, роза, порталы.
- Рыцарь — 192 кадра ASCII-арта (стойка, ходьба, бег и прыжок в 8 направлениях), коровы — 642 кадра; картинки не нужны. Исходные атласы и скрипты перевода — в `assets/` и `tools/`.
- Отрисовка через WebGL2: все символы кадра уходят на GPU одним вызовом. Без WebGL2 работает запасной путь через 2D canvas.

## Запуск

Открой `index.html` в браузере — сервер и сборка не нужны (работает и с `file://`).

Через HTTP: `npx http-server .` (или любой статический сервер) и открыть `http://localhost:8080/`.

Онлайн: https://ascii-meadow.aloster36.workers.dev/ (Cloudflare Workers, бесплатный тариф; публикуется из `main` при каждом пуше, репозиторий остаётся приватным).

## Управление

| Действие | Клавиши |
| --- | --- |
| Ходьба | WASD / стрелки, или тянуть пальцем |
| Бег | Shift, или тянуть далеко от рыцаря |

## Редактор карты

Карту меняют прямо в игре:
1. Открыть игру — https://ascii-meadow.aloster36.workers.dev/ (или `index.html` локально) — и нажать **M** или кнопку «Редактор карты» внизу слева. Пока мир строится, редактор открыт всем; когда проект будет готов, его спрячем за тайной комбинацией. `?edit=0` выключает его для страницы.
2. Справа панель:
   - **Кисти** — трава, высокая и низкая трава, земля, камни, цветы, тропа, «Вода» и «Болото» (вода с кочками, осокой и кувшинками; рыцарь туда пока не заходит, коровы тоже), «Стереть» (пустая земля: ни травы, ни тропы) и «Как было» (вернуть сгенерированное); размер — ползунок, колесо мыши или `-`/`=`. Галочка «Сгенерированная тропа» убирает всю тропу разом.
   - **Туман** — «Лёгкий туман» и «Густой туман» рисуют туман (он клубится и движется вместе с остальным, жар костров его разрежает), «Убрать туман» стирает и нарисованный, и сгенерированный.
   - **Объекты** — дерево (7 вариантов), сухое дерево (4), куст (6), корова, костёр, старт рыцаря; вариант — `[` `]` или колесо.
   - **Замок** (`L`) — клик ставит подножие замка (ворота) в эту точку; рамка показывает, сколько места он займёт. Вместе с ним переезжают лестница, жаровни у ворот, тень и сгенерированная тропа; нарисованное остаётся на месте.
   - **Выбрать и двигать** — клик выделяет, перетаскивание двигает, `Delete` удаляет. Удаляется всё: деревья, кусты, коровы, костёр и жаровни у ворот. Старт рыцаря только двигается — где-то он должен появиться. Костёр, поставленный на террасу или лестницу, встаёт на их высоту.
   - **Мини-карта** — весь мир; клик переносит камеру.
3. Камера: WASD/стрелки (Shift — быстрее), правая кнопка или пробел + мышь — тащить. Масштаб — `Ctrl` + колесо или щипок на тачпаде, `Q`/`E`, кнопки «−»/«+» (от 35% до 200%), `R` — 100%; при выходе из редактора игра снова в своём масштабе. Отменить/повторить — `Ctrl Z` / `Ctrl Shift Z`.
4. **«Сохранить»** (`Ctrl S`) скачивает `map.js`. Файл отдаёшь Claude — он кладёт его в `src/data/map.js`, и после пуша в `main` Cloudflare обновляет сайт. «Открыть…» загружает сохранённый файл обратно, «Играть отсюда» закрывает редактор и ставит рыцаря в центр экрана.

Черновик сохраняется в браузере, пока файл не сохранён.

Координаты карты — единицы модели замка, а не клетки экрана, поэтому нарисованное стоит на тех же местах на любом мониторе и телефоне. Пустая карта (`null`) = мир, сгенерированный кодом, как раньше.

## Структура

```
index.html            точка входа: разметка, стили, скрипты по порядку
styles/main.css       оформление HUD и холстов
src/
  core/               общее состояние, шум, камера, ввод, шаг симуляции (game.js)
  renderer/           атласы глифов, батч, WebGL2 и 2D, свет костра на рыцаре, сборка кадра (render.js)
  world/              поле и тропа, трава, ветер, мелкая жизнь, замок, туман, растения, огни, точки «E»
  entities/           сущности, рыцарь, коровы, 2D-риг
  systems/            движение и направления, анимация рыцаря (плащ, ноги), коллизии
  data/               кадры рыцаря и коров (генерируются инструментами) и карта map.js (сохраняется редактором)
  editor/             редактор карты (кнопка внизу слева или M)
  main.js             игровой цикл и старт
assets/               исходные атласы (игра их не загружает)
tools/                перевод атласов в ASCII-кадры и проверки масок
notes/                заметки (хранилище Obsidian)
```

Скрипты — обычные `<script src>` без модулей и сборки: так игра открывается напрямую из файловой системы. Все файлы делят одну глобальную область видимости, поэтому **порядок подключения в `index.html` важен**. Подробно — в `notes/Техническая архитектура.md`.

## Разработка

### Как устроена загрузка
Каждый файл — обычный `<script src>`. Все файлы делят одну глобальную область видимости, как раньше внутри единого скрипта. Отсюда три правила:
- **Порядок `<script>` в `index.html` важен.** Код, который выполняется при загрузке (таблицы, разбор кадров, `initGL`), видит только то, что подключено выше. Функции, вызываемые из кадра (`simulate`/`render`), работают при любом порядке.
- **Имена верхнего уровня уникальны во всём проекте** и не совпадают со свойствами `window` (`name`, `top`, `frames`, `status`…). Повтор ловит `node tools/check/lint.cjs`.
- **В `index.html` нет кода и стилей.** Только разметка и подключения; это проверяет `tools/check/resources.cjs`.

### Новый персонаж
1. **Кадры** — в `src/data/<имя>-frames.js`, только данные: `const <ИМЯ>_ART = [...]`. Их генерирует инструмент в `tools/<имя>/` из атласа в `assets/<имя>/`. Формат как у рыцаря (`src/data/knight-frames.js`) или упакованный как у коровы (`src/data/cow-frames.js`).
2. **Логика** — в `src/entities/<имя>.js`:
   - разбор кадров один раз при загрузке, текст потом очищается (`ART.length = 0`);
   - индекс анимаций по направлениям d8, как `CIX` у коровы;
   - `update<Имя>(dt)` и `draw<Имя>(e)`.
3. **Сущность** создаётся через `mk(...)` (`src/entities/entities.js`) и добавляется в `ents`. Рисуется из `drawEntity` (`src/renderer/entities.js`) по `e.cls`; её `charDims`/`geomOf` задают размер и опорную точку.
4. **Обновление** — вызов `update<Имя>(dt)` в `simulate()` (`src/core/game.js`) в нужном месте порядка.
5. **Подключение** — `<script>` данных, затем сущности, рядом с `knight`/`cow` в `index.html`.

### ASCII-анимации
- **Где хранятся:** только в `src/data/`, в виде текста. Каждый кадр — строки символов рампы ` .:-=+*#%@` (яркость) и `'` (тёмная подложка); первая строка кадра — отступ сверху.
- **Анимация двигает готовые символы** и никогда не пересчитывает дизеринг в кадре: пересчёт даёт мерцание. Смещения клеток — в `src/systems/animation.js` (рыцарь: плащ, ноги, дыхание).
- **Разметка кадров рыцаря** (контуры плаща `KCLOAK*`, полотнище `KTABARD`, клинки `KSW`) лежит рядом с ним, в `src/entities/knight.js` и `src/data/knight-frames.js`.

### Новый объект окружения
- **Свой файл** в `src/world/`. Запекание — один раз в `build()` (`src/world/terrain.js`, через `buildWorld`/`buildFlora` или свою `buildX`), а не в каждом кадре.
- **Обновление** — `updateX(dt)` в `simulate()`.
- **Отрисовка** — из `render()` (`src/renderer/render.js`). Объект с опорой на землю вставляется в список `order`, тогда его перекрывают трава и персонажи. Рисовать через `gput`/`blit`/`grect` в батч: одна отрисовка GPU на кадр.
- **Твёрдый объект** — условие в `blocked()` (`src/systems/collisions.js`). Объект с действием «E» — точка в `props` (`src/world/world.js`).
- **Свет на рыцаре** от нового источника считается в `fireLightAt` (`src/renderer/lighting.js`).

### Новый модуль: чек-лист
1. Файл в своей папке: `core`, `renderer`, `world`, `entities`, `systems`, `data`.
2. `<script>` после всего, что нужно ему при загрузке, и до `src/core/input.js`. `src/main.js` всегда последний.
3. Вызовы из `simulate()`/`render()` — порядок там и есть порядок игры.
4. Горячие функции (на клетку или глиф) без замыканий и выделения объектов.
5. Прогнать проверки (ниже) и обновить `notes/Техническая архитектура.md`.

### Запуск и проверки
- **Игра:** открыть `index.html` (сервер не нужен) или `npm run serve` → `http://localhost:8080/`.
- **Инструменты проверки:** `npm ci`, затем `npx playwright install chromium`. Самой игре они не нужны.
- `npm run check:static`: синтаксис всех скриптов, ESLint по скриптам в порядке загрузки, ресурсы страницы.
- `npm run check:browser`: smoke-тест в Chromium. Мир собран, WebGL2 и 2D рисуют, ходьба, бег, прыжок, порыв, мышь, состояния коров, касания, ресайз, старт в окне нулевого размера, консоль без ошибок.
- **Сравнение «до/после»** при переносе кода (картинка должна совпасть попиксельно): `tools/check/README.md` (`det.cjs` + `diff.py`). Производительность — `tools/check/perf.cjs`.
- **Один HTML-файл** (для артефакта): `python3 tools/bundle.py dist/ascii-meadow.html`.
- **CI** (`.github/workflows/ci.yml`) на каждый PR в `main` и push в `main`:
  - статические проверки и склейка;
  - smoke-тест с `file://`, по HTTP из `/ASCII-Meadow/` и на склейке;
  - на PR — **обязательное** попиксельное сравнение с базовой веткой в шести сценариях: рыцарь, 8 направлений, коровы, замок, 2D, мобильный.

  Если PR намеренно меняет картинку, на него ставится метка `visual-change`: сравнение всё равно выполняется и выкладывает diff-изображения, но не блокирует. При падении снимки и логи сохраняются как артефакты.
- **Cloudflare** (Workers Builds, подключён к GitHub): каждый пуш в `main` — деплой на сайт, каждая другая ветка — превью-сборка (проверка «Workers Builds: ascii-meadow» на PR). `npm ci` через скрипт `prepare` кладёт сайт в `dist/` (`tools/build_site.sh`: `index.html`, `styles/`, `src/`), `wrangler.jsonc` отдаёт `dist/` как статические файлы — без кода Worker. Прежний GitHub Pages workflow удалён: в приватном репозитории на бесплатном тарифе Pages недоступен.
