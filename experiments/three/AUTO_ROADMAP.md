**Версия:** 2026-10-16. **Журнал реализации:** [ENVIRONMENT_MIGRATION_LOG.md](ENVIRONMENT_MIGRATION_LOG.md). **GitHub-трекер:** [issue #53](https://github.com/aostera/ASCII-Meadow/issues/53).

> **Порядок изменён владельцем 2026-10-16:** сначала системный перенос, художественная детализация архитектуры в конце.
>
> **Текущие пункты (параллельно, независимые ветки):** `T04` тени, `T05` флора, `T06` остальные объекты, `T07` mobile/редактор.
>
> **Отложено:** `T02`/`T03` (детализация замка и руин) — `PARKED` до завершения системных пунктов; draft [PR #54](https://github.com/aostera/ASCII-Meadow/pull/54) не мержить и не развивать в рамках очереди. Запуски раз в час, пункты могут занимать несколько запусков.

## Базовые принципы

1. Всё выполняется в **`experiment/threejs-ascii-prototype`**, либо в отдельной `feat/three-*` / `fix/three-*` ветке от её свежего tip. Никогда не сливать в production `main` без отдельного прямого разрешения владельца.
2. Не переписывать `src/data/map.js`, дизайнерскую карту, персонажные спрайты, исходные цвета/альфу. Для gameplay использовать существующий native Three WebGL2 runtime, а не автономный procedural-вьювер. Канвас/контекст WebGL один; Canvas2D fallback не терять.
3. Стиль: **готический, погибающий, тёмный**, по ранее утверждённому визуальному направлению. Детализация замка и руин, окружение и визуальная логика принадлежат этому плану. Ссылки на недоступные эскизы **не объявлять точной сверкой**, пока они реально не доступны.
4. **Персонажи и Tripo пока не трогаем**. Отдельные открытые PR #38–45/#52, включая риг, должны оставаться изолированными. Не расходовать кредиты.
5. Для каждой технической задачи нужны: реальное изменение исходного кода (если применимо), детерминированные проверки Chromium WebGL2 на desktop/phone viewport, карта без изменений, отсутствие регрессий, документирование точных SHA/CI, известного визуального долга и ограничений. Phone viewport **не** заменяет физический Android Chrome или iOS Safari.
6. **Выполнено** = код в experiment + специализированный QA green + нет существенных открытых регрессий + описание в журнале + обновление этой очереди/issue. Если рискованное изменение не проходит — PR остаётся draft, пункт остаётся `IN_PROGRESS`, переход запрещён.

Художественная оценка — отдельно: владельцу периодически отправляется пачка скриншотов native-кадров, его замечания заводятся как visual debt и не блокируют системные пункты. Для этапа, требующего физического устройства/недоступного инструмента, фиксировать `BLOCKED_EXTERNAL` и конкретный недостающий артефакт; не выдавать эмуляцию за успех и продолжать другую безопасную независимую часть.

**Скорость итераций:** визуальные изменения сначала проверять локальным headless-прогоном on/off/on (изменённые пиксели + `MEADOW_MAP` без изменений) и только потом отдавать в CI.

## Рабочий протокол автоматического продолжения

1. Прочитать этот документ, [issue #53](https://github.com/aostera/ASCII-Meadow/issues/53), последние GitHub PR / Actions / `ENVIRONMENT_MIGRATION_LOG.md`. Никогда не доверять только текстовому статусу: подтвердить фактический SHA и ветку.
2. Найти активные `IN_PROGRESS` этапы, снять уже завершённые по реальным доказательствам. На одном запуске продвигать тот активный этап, где есть самый короткий путь к результату (не ждать CI одного пункта, если можно работать над другим); `PARKED` не брать, пока не закрыты T04–T08.
3. Кодить и проверять на `feat/three-*` от текущего experiment tip; PR в `experiment/threejs-ascii-prototype`. Перед merge — зелёные профильные QA + проверки редактора/depth, отсутствие map/alpha/physics регрессий. Не мержить плохую ветку.
4. После принятия обновить статус `DONE`, внести PR/CI/метрики в `ENVIRONMENT_MIGRATION_LOG.md`, синхронизировать issue #53, обновить список **Текущих пунктов** и продолжить оставшиеся. Достижение одного этапа не снимает открытый visual debt.
5. В сообщениях пользователю кратко показывать конкретные выполненные изменения и ссылку на preview; если blocked — причину, ссылки, что осталось. Без бесконечных отчётов «работаю», без фиктивной фоновой непрерывной работы.
6. **Scheduled automation:** один запуск раз в час. Ограничения: это периодический пуск модели, **не реакция в секунду закрытия PR**, и доступность GitHub/plugin инструментов на запланированных запусках нужно фактически проверить. Если нет доступа — сообщить точный blocker, не обещать выполненных коммитов. При возобновлении живого чата продолжать тот же этап без дублирования.
